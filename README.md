## Run

Use Flutter 3.47.4 / Dart 3.13.3 or a compatible newer stable SDK with Android SDK and JDK installed.

```text
flutter pub get
flutter analyze
flutter test
flutter run
flutter build apk --release
```

The actual client configuration for Firebase project `recipebox-95b1b` is included in `lib/main.dart` and `android/app/google-services.json`. No admin keys are used. Email/Password Authentication and Firestore are enabled; rules are saved in `firestore.rules` and deployed. If using another Firebase project, replace only client configuration and deploy the same rules with Firebase CLI.

The release build uses the standard local Android debug signing key for an installable exam APK, not Play Store publication. `android/local.properties` is machine-specific and is regenerated by Flutter. Kotlin incremental compilation is disabled to support Windows projects and pub caches on different drives.

## Architecture

- `lib/app.dart`: authentication gate; in-place public/auth/List navigation removes authentication history after successful sign-in.
- `lib/core/`: shared theme, allowed values, exact validators.
- `lib/models/recipe.dart`: schema, canonical identity, sorting/filtering and category summaries.
- `lib/services/recipe_repository.dart`: owner-filtered live Firestore streams and transactional writes.
- `lib/screens/`: Home, Register/Login, List and Detail/edit.
- `lib/widgets/`: common layout, fields, banners, favorite button and shared add/edit form.
- `test/`: validation boundaries, sort/filter/summary logic, responsive Home and auth validation behavior.
- `integration_test/`, `test_driver/`: real Android/Firebase flows and actual screenshot capture.

## Firestore schema and uniqueness

All saved records live in `recipes`. Required fields: `id`, `userId`, `name`, `category`, `difficulty`, `cookTime`, `favorite`, `createdAt`. Optional `servings` is omitted when empty; optional `notes` defaults to empty string. Integer minutes are 1–600, integer servings 1–20, name up to 80 characters and notes up to 300. Categories and difficulties are the exact assignment enums.

Document ID is `userId + '_' + uppercaseHex(UTF8(trim(name).toLowerCase()))`. Rules recompute and enforce it, so direct client writes cannot create a second case-insensitive name under any alternate ID. This also supports recipe names containing slash and Unicode without path collisions. Because names are part of identity, a rename uses one transaction to check the new ID, delete the previous document, and create the new one, preserving `createdAt` and concurrent favorite changes. Case-only renames keep the same ID. Direct grader writes must follow this documented ID convention and put the same value in the `id` field.

Rules deny all other collections, anonymous access, foreign-owner access, extra fields, malformed types/values, and changing ownership or creation time. Owner-constrained queries require `where('userId', isEqualTo: currentUid)`; rules are not filters. No composite index is necessary; sorting/search/summary run locally over the authenticated user's live query.

## Evidence and submission

Generated artifacts, test logs, required screenshot checklist and final audit are under `outputs/`. Inputs (assignment, design system, reference image) remain unchanged. `outputs/requirements.md` contains the manual checklist and required screenshot order. Publication requires explicit user authorization; the report cannot contain real repository/APK URLs until those resources exist.

Run real emulator verification with:

```text
flutter drive --driver=test_driver/integration_test.dart --target=integration_test/app_test.dart -d emulator-5554 --dart-define="TEST_EMAIL=$env:RECIPEBOX_TEST_EMAIL" --dart-define="TEST_PASSWORD=$env:RECIPEBOX_TEST_PASSWORD" --dart-define="ISOLATION_EMAIL=$env:RECIPEBOX_ISOLATION_EMAIL"
```

Set the three environment variables locally before running that PowerShell command. Test credentials are supplied at invocation and are not stored in the public source. The test creates a separate registration account, signs in to the seeded grader account, exercises real CRUD and filters, captures actual UI PNGs, deletes only its temporary recipe, and checks a separate empty account. Local backend checks in `outputs/test-backend.ps1` use public client APIs, never admin credentials. Grading credentials remain in the private local `outputs/test-account.md` and the submission report.
